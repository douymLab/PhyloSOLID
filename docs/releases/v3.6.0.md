# Version 3.6.0

## Highlights

- **Pre-QC and post-QC results:** Final output now includes the Step 7 snapshot in `phylo_unpruned/` and the Step 8 result in `phylo/`. Both bundles remove all-zero inferred matrix rows/columns and collapse the corresponding tree nodes.
- **Consistent pruning safeguards across modes:** Zero-Omega handling, fallback status and CV selection are aligned across scRNA, scDNA and SpaceTracer; binary-matrix mode uses the same safe pruning-ratio calculation.
- **Resolution backoff across entry points:** scRNA, SpaceTracer and binary-matrix enable grouping-conflict-guided auto-resolution backoff by default. scDNA accepts the same options while retaining its fixed resolution of `0.1`.
- **Refreshed demos and documentation:** All three packaged demos include pre-QC/post-QC results and updated plots. A shorter README links to complete usage, parameter and output-stage guides.

---

## What's New

### Pre-QC and post-QC export

- Preserve a deep snapshot after Step 7 refinement and before Step 8 quality control, including the tree, inferred matrix, ROOT mutations and conflict state.
- Export the selected run as two bundles:
  - `phylo/`: Step 8 result, or the Step 7 snapshot when explicitly marked `pre_fallback`.
  - `phylo_unpruned/`: Step 7 snapshot before Step 8 QC.
- Clean all-zero inferred matrix rows/columns in both bundles, collapse corresponding tree nodes, and align each observed matrix to its own inferred matrix.
- Add `output_stage.json` to each bundle, recording its source stage, dimensions, removed ghost mutations and Omega. Add `README_phylo.txt` to explain the output layout.
- Retain the existing mode-specific final-results directory names and tree/matrix filenames.

### Resolution backoff

- Add `--resolution_backoff_threshold` (default `0.10`) and `--disable_resolution_backoff` to all four direct tree-building entry points.
- Start from the existing DQI-based auto resolution. If the grouping-conflict fraction exceeds the budget, decrease resolution by `0.1` on the same graph and accept the first passing candidate.
- Bound the search by the configured minimum resolution (normally `0.5`) and at most 20 decreases. If no candidate passes, retain the original auto partition and report the unmet budget.
- Write a JSON decision record, trajectory TSV and initial/selected per-cell conflict tables for auditing.
- Fixed resolution takes precedence over backoff. **scDNA keeps its fixed `0.1` default**, so backoff is inactive unless its parameter dictionary selects automatic resolution.

### Pruning policy and CV selection

- Use a shared safe pruning ratio: `(Omega_pre_QC - Omega_final) / max(Omega_final, 1e-8)`.
- Treat a valid zero/zero-Omega tree as ratio `0`; a positive pre-QC score with zero final Omega receives a large ratio.
- Prefer usable post-QC (`final`) candidates over `pre_fallback` candidates.
- Among final candidates passing the pruning guard, select by `Omega_final`, then `Omega_pre_QC`, then CV value. If none pass, select by `Omega_pre_QC`, then `Omega_final`, then CV value.
- If all successful candidates are pre-QC fallbacks, select by `Omega_pre_QC`, then CV value, without labeling the output confident.
- Include ROOT-assigned mutations consistently in pre-QC scoring, CV scoring and exports.

### Demos and documentation

- Regenerate tree-building results and circos plots for the scRNA, scDNA and binary-matrix demos, reusing their existing upstream feature/tree-input files.
- Ship both cleaned phylo bundles, stage metadata, updated CV summaries where applicable, and portable source/input provenance under `demo/*/expected_output/`.
- Updated example dimensions (cells × mutations):

  | Demo | Step 7 pre-QC | Step 8 post-QC |
  |---|---:|---:|
  | scRNA | 433 × 17 | 352 × 17 |
  | scDNA | 22 × 78 | 22 × 78 |
  | Binary matrix | 13 × 21 | 8 × 19 |

- Reorganize the README around mode selection, installation, demos and outputs; move detailed material into `docs/`.
- Add a complete parameter reference covering all four entry points, 37 distinct mode-dictionary fields, configuration paths and runtime controls. Document currently inactive settings explicitly.

### Bug Fixes

- Fix zero-Omega division and inconsistent zero/zero handling in pruning metrics and summaries.
- Prevent pre-QC fallback trees from being treated as normal post-QC candidates or labeled confident.
- Make CV ties deterministic by including the CV value in the selection order.
- Correct outdated pruning-threshold text and propagate output-stage metadata to summaries.
- Ensure inferred matrix files are written even when the optional conflict-free plotting check does not pass.

### Breaking Changes

- **`phylo_unpruned/` semantics changed:** It now contains the Step 7 pre-QC snapshot, rather than the post-QC tree before all-zero export cleanup. Downstream analyses relying on the former meaning should be updated.
- **Both bundles are cleaned:** `phylo_unpruned/` no longer retains all-zero inferred matrix rows/columns solely for debugging.
- **Scores and selected trees may change:** ROOT-consistent scoring, zero-Omega handling, fallback priority, deterministic ties and enabled auto-resolution backoff can change results relative to v3.5.0.
- Existing output directories are not migrated automatically. Regenerate results to obtain the new pre-QC/post-QC layout.

## Notes

- Recommended for users comparing QC effects or running CV threshold search across modes. Review regenerated outputs when upgrading from v3.5.0.
- The grouping-conflict budget and pruning guard are operational heuristics, **not calibrated confidence probabilities, estimated doublet rates or guarantees of biological accuracy**.
- CV and resolution-backoff options belong to the direct Python tree-building entry points; the top-level pipeline CLI does not automatically forward them. See the parameter reference for supported settings and activation conditions.
- Validation includes **20 regression tests**, pruning integration checks, three regenerated demo tree-building/visualization runs, and documentation/parameter inventory checks. The demo refresh did not repeat BAM preprocessing.
- Full local demo runs, logs, caches and machine-specific configuration remain ignored. Packaged example results are kept in `expected_output/`.
- Copy `config/paths.yaml.template` to `config/paths.yaml` and set local tool/resource paths. Keep circos dependencies in a separate visualization environment.
- For detailed usage, see the [README](https://github.com/douymLab/PhyloSOLID/blob/main/README.md), [parameter reference](https://github.com/douymLab/PhyloSOLID/blob/main/docs/parameters.md) and [output-stage guide](https://github.com/douymLab/PhyloSOLID/blob/main/docs/phylo_output_stages.md).
